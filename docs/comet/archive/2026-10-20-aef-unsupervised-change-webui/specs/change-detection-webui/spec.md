# 变化检测 WebUI 规格

## 目的

本 capability 提供一个本地 NiceGUI 应用，按 AlphaEarth Foundations (AEF) 论文补充材料 S4.1 的无监督变化检测流程，对同一瓦片、同一视图的两帧 64 维像素嵌入做逐像素比较，输出可交互的变化程度热力图，并与 `data/spectral/gallery` 中的原始图像并排呈现。

## 输入数据契约

### 嵌入

- 路径：`data/spectral/tiles/<tile>/embeddings/<view>.npy`
- 形状：`(frames, 128, 128, 64)`，`float32`，每像素向量已为单位长度。
- 帧元数据：同目录 `<view>_index.json`，`frames[i]` 提供 `date_utc`、`timestamp_ms`、`parent_raw_index`、`sensor_id` 等字段。

### 有效像素掩膜

- 路径：`data/spectral/tiles/<tile>/distance_maps/<sensor>_*.npz` 中的 `common_mask`，`bool`，形状 `(128, 128)`。
- `<sensor>` 取 view 名的前缀（`sentinel2` 或 `landsat`）。同一瓦片下不同传感器各有独立掩膜，其内容不同，必须按传感器选取，不得取目录中第一个文件，也不得回退到其他传感器的掩膜。
- 缺失对应传感器的掩膜时必须报错，不得使用全 True 掩膜。
- 掩膜的使用受界面开关控制：开关开启（默认）时，掩膜为假的位置不参与任何统计且热力图中以中性灰显示；开关关闭时不应用掩膜，全部像素参与着色与统计。
- 掩膜外的嵌入向量本身可能包含有效数值（实测 C01 的 413 个掩膜外像素范数为 1、无 NaN、两帧互不相同），因此关闭掩膜后必须按正常距离着色，不得因为"曾被掩膜排除"而输出灰块或异常颜色。

### 图像

- `data/spectral/gallery/index.json` 为数组，元素含 `id`、`source`、`date`、`image`；`image` 以 `spectral/` 为前缀，相对 `data/` 解析为 `data/spectral/...`。
- 通过 `(id=tile, source=encoder_source, date=date_utc)` 精确匹配得到该帧的 PNG。首末帧必须能匹配；匹配失败时界面显示明确提示，不以近似日期代替。
- gallery 文件按 `{tile}_{source}_{帧序号}.png` 命名，日期到文件名的映射只能经 index 完成。缺失提示必须说明该命名模式与当前瓦片已有文件，不得拼接日期形状的伪文件名。
- 缺失提示区分两种情况：索引无该日期记录；索引有记录但文件不存在（后者给出记录中的路径）。
- gallery PNG 为预渲染多面板图：Sentinel-2 为 RGB/NIR/SWIR 三面板，Landsat 为 RGB/NIR/SWIR/Thermal 四面板，每面板 256×256，纵向位于第 48–303 行；图上方有标题、下方有说明。本 capability 按原样完整显示，不裁剪。

## 计算

### 距离

对两个帧 `i`、`j` 的嵌入张量 `X`、`Y`，逐像素计算：

```
cos(p) = <X[p], Y[p]> / (||X[p]|| * ||Y[p]||)
d(p)   = (1 - cos(p)) / 2
```

实现要求：

- 计算前对每个像素向量做 L2 归一化；零范数向量按无效处理。
- `d` 的取值截断在 `[0, 1]`。
- 该定义与论文公式 (8) 一致，`0` 表示两帧完全相同，`1` 表示方向相反。
- 必须独立于数据包自带的 `distance_maps` 数值实现；后者仅用于掩膜。

### 帧对

- `frames == 2`：固定使用第 0 帧与第 1 帧，不提供帧对选择。
- `frames > 2`：提供帧对选择，候选为全部 `i < j` 组合；默认选中首帧与末帧。
- `frames < 2`：该视图不进入选择器。对单帧自比会得到恒为 0 的距离图，属于误导性结果。界面在元信息中列出被排除的视图名与原因。
- 全部 33 个瓦片共 265 个视图，其中 225 个可用；40 个单帧视图（C05/C06/C10/C12/C17/C18/C19/C21 的 Landsat 视图）被排除。

### 阈值量程

阈值控件的量程随当前图像对自适应，不再固定为 `[0, 1]`。

记参与统计的像素集合为 `S`（由 `common_mask` 开关决定），`m = max(d[p] for p in S)`。量程为左开右闭的 `(0, x]`：左端 `0` 不提供，最小可选值为一个步长。

1. 步长 `step` 取约 `m/100`，保留到合适精度（不小于 `0.0001`），使量程小时仍有约 100 个档位。
2. 上界 `x` 取严格大于 `m` 并对齐到 `step` 的最小值，即 `x = ceil(m / step + ε) * step`，并截断到 `1.0`。
   - 必须保证 `count(d > x) == 0`，即滑块到达上界时没有任何高亮像素。
   - 量程左端为排除值：滑块与数值框的最小值均为 `step`，因此阈值永远取不到 `0`，实际可选范围为 `(0, x]`。
   - 若 `m == 0`（所有像素距离为 0），令 `x = step`，此时最小值与最大值同为 `step`，任何阈值下高亮数均为 0。
3. 默认阈值：
   - 当 `x >= 0.30` 时取 `0.30`；
   - 当 `x < 0.30` 时取 `x / 2`；
   - 均对齐到 `step` 并限制在 `[step, x]`（左端不可为 0）。
4. 切换瓦片、视图、帧对或 `common_mask` 开关时，重新计算 `step`、`x` 与默认阈值。

### 统计

在参与统计的像素集合内计算。该集合由 `common_mask` 开关决定：开启时为掩膜内像素，关闭时为全部 16384 个像素。

- 参与统计的像素总数；
- 高于阈值的像素数与占比 `count / total`；
- 距离的中位数、p95、最大值。

阈值或掩膜开关变化时这些数值实时刷新。统计标签需说明当前分母来自哪种掩膜状态，避免把两种口径的数字混淆。

## 界面

### 控件

1. **瓦片选择器**：列出 `data/spectral/tiles/` 下全部瓦片，显示类别和 split 作为辅助信息。
2. **视图选择器**：列出所选瓦片中可做两帧比较的视图，默认 `sentinel2_full`；被排除的单帧视图在元信息中说明。
3. **帧对选择器**：仅当 `frames > 2` 时出现。
4. **阈值滑块**：量程 `(0, x]` 由当前图像对自适应计算（见「阈值量程」），最小值为 `step`、最大值为 `x`，步长自适应约为 `x/100`；同时提供数值输入框，其最小值同为 `step`，二者双向同步，数值精度随量程调整。滑块与数值框均需实时显示当前阈值，并显示当前量程上界 `x`。
5. **显示模式选择器**：三种模式，见下节。默认「半透明红色叠加」。
6. **common_mask 开关**：默认开启。开启时应用掩膜，掩膜外像素显示中性灰且不计入统计；关闭时全部像素参与着色与统计。切换后无需刷新页面即可看到热力图与统计变化。

### 热力图

以 `128 x 128` 距离场为数据源，用连续色阶渲染，固定色标 `[0, 1]` 并显示色条。

- 掩膜开关开启时，掩膜外的像素显示为中性灰，不参与色阶；关闭时全部像素按距离着色。
- 热力图与显示模式无关的底图行为保持一致，切换模式不改变距离数值。
- 热力图上叠加超阈值区域时，阈值使用滑块当前值；距离色阶仍固定为 `[0, 1]`，与阈值量程解耦。

### 显示模式

1. **半透明红色叠加**（默认）：在完整连续热力图上，对 `d > threshold` 的像素叠加半透明红色。
2. **二值掩膜**：`d > threshold` 的像素显示为红色，其余有效像素显示为深色；掩膜外仍为中性灰。
3. **灰底彩色高亮**：`d > threshold` 的像素保留连续热力图配色，其余有效像素转为灰度。

### 图像区域

- 显示与所比较两帧对应的两张 gallery 原始整幅图，各自标注 `date_utc` 与来源。
- 布局为：一侧是热力图与统计，另一侧是两张整幅图纵向排列；整幅图宽度较大，容器允许横向滚动。
- 图像缺失或匹配失败时，显示具体缺失的日期、gallery 命名模式与该瓦片现有文件；索引有记录但文件不存在时还要给出记录路径。

### 元数据展示

在页面上显示当前瓦片的 `split`、`category`、视图名、两帧日期、帧数，以及距离的中位数、p95、最大值和高阈值像素统计。

## 服务与运行

- 入口为单个 Python 脚本，使用 NiceGUI 启动。
- 默认监听 `127.0.0.1:8080`，主机与端口可由命令行参数覆盖。
- 页面初次加载时自动选中默认瓦片、默认视图和默认阈值，无需用户操作即可看到完整结果。
- 所有依赖安装在项目 `.venv`，运行命令使用 `.venv/Scripts/python.exe`。
- 不访问网络；图像与数据全部来自本地文件。
